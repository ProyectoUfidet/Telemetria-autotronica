El proyecto

Del componente al dato útil

La telemetría consiste en medir variables a distancia y enviar los datos a otro equipo para registrarlos o visualizarlos. En autotrónica se puede aplicar al monitoreo de temperatura, tensión, estados de sensores y variables del vehículo, siempre usando interfaces eléctricas adecuadas.

01 · Hardware

Plataforma ESP32 y periféricos

El hardware es la parte física: microcontrolador, sensores, módulos de comunicación, alimentación, conectores y cableado.

Imagen de referencia suministrada: pinout de una ESP32 DevKitC. El pinout exacto depende de la placa y de la variante del módulo.

ESP32: unidad de control

El ESP32 es una familia de microcontroladores con conectividad inalámbrica. En una placa de desarrollo, ejecuta el programa, lee entradas, procesa datos y controla salidas. El módulo ESP-WROOM-32 clásico integra Wi‑Fi y Bluetooth y dispone de interfaces como GPIO, ADC, SPI, I²C y UART; las capacidades concretas dependen de la variante.

InterfazUso típico
GPIOEntradas y salidas digitales para señales compatibles.
ADCLectura de ciertas señales analógicas dentro de los límites eléctricos.
SPIComunicación rápida con periféricos como el módulo LoRa.
I²CBus de dos líneas usado por sensores y expansores compatibles.
UARTComunicación serie, por ejemplo con un equipo o módulo externo.
Seguridad eléctrica: los GPIO del ESP32 trabajan con lógica de 3,3 V y no son tolerantes a 5 V. No conectar directamente señales automotrices de 12 V, bobinas, inyectores ni líneas de comunicación del vehículo. Usar acondicionamiento, protección y una interfaz diseñada para cada señal.

02 · Software

Firmware, herramientas y aplicación móvil

El software define qué hace el circuito, cómo interpreta los datos y cómo los presenta al usuario.

Firmware

Arduino IDE / ESP-IDF

El firmware es el programa que se ejecuta dentro del ESP32. Puede inicializar sensores, leer entradas, filtrar valores, controlar eventos y enviar datos. Arduino IDE facilita comenzar; ESP-IDF ofrece el entorno oficial de desarrollo de Espressif.

Protocolo de datos

Definir un formato consistente —por ejemplo, TEMP=24.5;HUM=60— facilita separar los campos, validar datos y mostrar cada variable en su etiqueta correspondiente.

Agregar unidades, fecha/hora, estado de conexión y tratamiento de errores mejora la lectura.

03 · Fichas técnicas

Componentes de las imágenes

Las fichas siguientes parten de las fotografías aportadas y se pueden ampliar con datasheets, fotos propias y pruebas de laboratorio.

LoRa RA-02 · SX1278

Módulo de radio para comunicación de largo alcance y bajo consumo. La variante mostrada trabaja habitualmente en la banda de 433 MHz y se comunica con el microcontrolador mediante SPI.

  • 3V3: alimentación de 3,3 V según el módulo.
  • GND: referencia eléctrica común.
  • SCK, MOSI, MISO, NSS: bus SPI.
  • RST y DIOx: reinicio y señales digitales/interruptores.
  • ANT/IPEX: conexión de antena; no transmitir sin la antena adecuada.

La ficha 7SEMI suministrada indica rango 410–525 MHz, SPI y alimentación típica de 3,3 V. Alcance real depende de antenas, obstáculos, potencia, configuración y normativa local.

DHT11 · Temperatura y humedad

Sensor digital básico para medir temperatura y humedad relativa ambiental. No mide directamente temperatura de motor ni fluidos automotrices y no está diseñado para ambientes severos del vehículo.

  • VCC: alimentación conforme a la versión del sensor/módulo.
  • DATA: comunicación digital de un hilo con protocolo propio.
  • GND: masa.
  • NC: en la versión de cuatro pines, el pin 3 suele no conectarse.

El módulo de tres pines puede incluir componentes adicionales y tener serigrafía distinta. Confirmar siempre el modelo y su documentación.

↔

Cadena de telemetría

Sensor → ESP32 → enlace de comunicación → receptor/app → usuario.

El sensor produce una medición; el firmware la valida y codifica; el enlace la transporta; la aplicación la decodifica y la presenta con unidades y estado.

Para telemetría vehicular real, añadir protección contra transitorios, filtrado, conversión de niveles y diseño de alimentación apropiado.

Nota de investigación: el pinout de la imagen ayuda a identificar conexiones, pero no sustituye al datasheet de la revisión exacta. Antes de cablear, comparar la serigrafía de la placa, el fabricante y el modelo.
04 · Laboratorio

Prácticas guiadas

Ejercicios iniciales para comprender el recorrido completo de los datos, desde la señal física hasta la pantalla del teléfono.

Práctica 1 · Leer DHT11

  1. Identificar versión y pines.
  2. Conectar alimentación y masa comunes.
  3. Leer temperatura/humedad con una librería compatible.
  4. Comprobar lecturas y registrar unidades.

Práctica 2 · Enviar datos al móvil

  1. Definir el formato del mensaje.
  2. Configurar el enlace compatible con la app.
  3. Recibir texto y separar campos en App Inventor.
  4. Mostrar valores y avisar si se pierde conexión.

Práctica 3 · Enlace LoRa

  1. Preparar dos nodos: emisor y receptor.
  2. Verificar alimentación, SPI, frecuencia y antena.
  3. Enviar paquetes con identificador y contador.
  4. Medir pérdidas, latencia y alcance en condiciones documentadas.
Para conectar con un vehículo: comenzar en banco con una fuente limitada en corriente. Las señales de sensores, CAN, alimentación y actuadores automotrices requieren interfaces específicas; una conexión incorrecta puede dañar la placa o el vehículo.

Preguntas frecuentes

Conceptos clave

¿ESP32 es hardware o software?

ESP32 es el microcontrolador/módulo físico (hardware). El firmware es el software que se programa para que lea sensores, procese valores y se comunique con otros equipos.

¿LoRa es lo mismo que Wi‑Fi o Bluetooth?

No. Son tecnologías de comunicación distintas. LoRa suele priorizar enlaces de largo alcance y baja tasa de datos; Wi‑Fi prioriza redes de mayor caudal y Bluetooth se usa habitualmente en enlaces cercanos. El alcance depende de la instalación y del entorno.

¿Puedo usar el DHT11 en el motor de un automóvil?

No es apropiado para medir directamente la temperatura de un motor o refrigerante. Para una aplicación automotriz se requiere un sensor con rango, encapsulado y acondicionamiento adecuados.

¿La página se actualiza sola cuando agrego nuevos archivos?

Emisor

ESP32 con DHT11 y LoRa: lectura de temperatura y humedad, transmisión cada dos segundos y activación del cooler cuando la temperatura supera los 26 °C.

emisor.ino
#include <SPI.h>
#include <LoRa.h>
#include <DHT.h>

#define DHTPIN 4
#define DHTTYPE DHT11

#define COOLER 27

#define LORA_NSS   5
#define LORA_RST  14
#define LORA_DIO0 26
#define LORA_FREQ 433E6

DHT dht(DHTPIN, DHTTYPE);

unsigned long tiempoAnterior = 0;
const unsigned long intervalo = 2000;

void setup() {
  Serial.begin(115200);

  pinMode(COOLER, OUTPUT);
  digitalWrite(COOLER, LOW);

  dht.begin();

  SPI.begin(18, 19, 23, LORA_NSS);
  LoRa.setPins(LORA_NSS, LORA_RST, LORA_DIO0);

  if (!LoRa.begin(LORA_FREQ)) {
    Serial.println("Error al iniciar LoRa");

    while (true) {
      digitalWrite(COOLER, LOW);
      delay(1000);
    }
  }

  Serial.println("Emisor LoRa iniciado");
}

void loop() {
  if (millis() - tiempoAnterior >= intervalo) {
    tiempoAnterior = millis();

    float temperatura = dht.readTemperature();
    float humedad = dht.readHumidity();

    if (isnan(temperatura) || isnan(humedad)) {
      Serial.println("Error al leer el DHT11");
      return;
    }

    // Control local del cooler
    if (temperatura > 26.0) {
      digitalWrite(COOLER, HIGH);
      Serial.println("Cooler del emisor: ENCENDIDO");
    } else {
      digitalWrite(COOLER, LOW);
      Serial.println("Cooler del emisor: APAGADO");
    }

    // Enviar datos al receptor por LoRa
    String datos = String(temperatura, 1) + "," +
                   String(humedad, 1);

    LoRa.beginPacket();
    LoRa.print(datos);

    if (LoRa.endPacket() == 1) {
      Serial.print("Temperatura: ");
      Serial.print(temperatura);
      Serial.print(" C | Humedad: ");
      Serial.print(humedad);
      Serial.println(" %");
    } else {
      Serial.println("Error al enviar por LoRa");
    }
  }
}

Receptor

ESP32 con LoRa y Bluetooth: recibe las mediciones, controla los indicadores LED y el cooler, y envía los datos a la aplicación móvil.

receptor.ino
#include <SPI.h>
#include <LoRa.h>
#include "BluetoothSerial.h"

// Bluetooth Classic
BluetoothSerial SerialBT;

// LoRa SX1278
#define LORA_NSS   5
#define LORA_RST  14
#define LORA_DIO0 26
#define LORA_FREQ 433E6

// Salidas
#define LED_VERDE    25
#define LED_AMARILLO 32
#define LED_ROJO     33
#define COOLER       27

float temperatura = 0;
float humedad = 0;

String estadoLED = "NINGUNO";
String estadoCooler = "APAGADO";

bool hayDatos = false;
unsigned long ultimoPaquete = 0;
unsigned long ultimoEnvioBT = 0;

const unsigned long tiempoLimite = 10000;
const unsigned long intervaloBT = 1000;

void apagarSalidas() {
  digitalWrite(LED_VERDE, LOW);
  digitalWrite(LED_AMARILLO, LOW);
  digitalWrite(LED_ROJO, LOW);
  digitalWrite(COOLER, LOW);

  estadoLED = "NINGUNO";
  estadoCooler = "APAGADO";
}

void controlarTemperatura() {
  apagarSalidas();

  if (temperatura < 23.0) {
    digitalWrite(LED_VERDE, HIGH);
    estadoLED = "VERDE";

  } else if (temperatura > 24.0 &&
             temperatura <= 26.0) {
    digitalWrite(LED_AMARILLO, HIGH);
    estadoLED = "AMARILLO";

  } else if (temperatura > 26.0) {
    digitalWrite(LED_ROJO, HIGH);
    digitalWrite(COOLER, HIGH);

    estadoLED = "ROJO";
    estadoCooler = "ENCENDIDO";
  }
}

void enviarBluetooth() {
  if (!SerialBT.hasClient()) {
    return;
  }

  if (!hayDatos) {
    SerialBT.println("NA,NA,SIN_DATOS,APAGADO");
    return;
  }

  SerialBT.print(temperatura, 1);
  SerialBT.print(",");
  SerialBT.print(humedad, 1);
  SerialBT.print(",");
  SerialBT.print(estadoLED);
  SerialBT.print(",");
  SerialBT.println(estadoCooler);
}

void setup() {
  Serial.begin(115200);

  pinMode(LED_VERDE, OUTPUT);
  pinMode(LED_AMARILLO, OUTPUT);
  pinMode(LED_ROJO, OUTPUT);
  pinMode(COOLER, OUTPUT);

  apagarSalidas();

  // Iniciar Bluetooth
  SerialBT.begin("Monitor_LoRa_ESP32");
  Serial.println("Bluetooth iniciado");

  // Iniciar LoRa
  SPI.begin(18, 19, 23, LORA_NSS);
  LoRa.setPins(LORA_NSS, LORA_RST, LORA_DIO0);

  if (!LoRa.begin(LORA_FREQ)) {
    Serial.println("Error al iniciar LoRa");
    while (true) {
      apagarSalidas();
      delay(1000);
    }
  }

  Serial.println("Receptor LoRa iniciado");
}

void loop() {
  int tamano = LoRa.parsePacket();

  if (tamano > 0) {
    String datos = "";

    while (LoRa.available()) {
      datos += (char)LoRa.read();
    }

    int separador = datos.indexOf(',');

    if (separador > 0) {
      float nuevaTemperatura =
          datos.substring(0, separador).toFloat();

      float nuevaHumedad =
          datos.substring(separador + 1).toFloat();

      // Aceptar temperaturas y humedades validas
      if (nuevaTemperatura >= -40.0 &&
          nuevaTemperatura <= 80.0 &&
          nuevaHumedad >= 0.0 &&
          nuevaHumedad <= 100.0) {

        temperatura = nuevaTemperatura;
        humedad = nuevaHumedad;

        hayDatos = true;
        ultimoPaquete = millis();

        controlarTemperatura();

        Serial.print("Temperatura: ");
        Serial.print(temperatura);
        Serial.print(" C | Humedad: ");
        Serial.print(humedad);
        Serial.print(" % | LED: ");
        Serial.print(estadoLED);
        Serial.print(" | Cooler: ");
        Serial.println(estadoCooler);
      }
    }
  }

  // Seguridad ante perdida de comunicacion LoRa
  if (hayDatos &&
      millis() - ultimoPaquete > tiempoLimite) {
    hayDatos = false;
    apagarSalidas();
    Serial.println("Sin datos LoRa: salidas apagadas");
  }

  // Actualizar la aplicacion cada segundo
  if (millis() - ultimoEnvioBT >= intervaloBT) {
    ultimoEnvioBT = millis();
    enviarBluetooth();
  }
}
